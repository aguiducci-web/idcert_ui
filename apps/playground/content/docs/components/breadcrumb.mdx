## Examples

### With leading icon

Replace the first crumb's text with a `Home` glyph to save horizontal space on
deep trails. Keep an `sr-only` label on the link so screen-reader users still
hear "Home" — the icon alone is not an accessible name.

<Example name="WithIcon" component="Breadcrumb"><WithIcon /></Example>

### Truncated trail

Long hierarchies wrap and push the current page off-screen on small viewports.
Drop a `BreadcrumbEllipsis` in place of the middle crumbs so the first link
and the current page stay anchored at the ends. The ellipsis is decorative
(`aria-hidden`); pair it with a dropdown if you need the hidden crumbs to
remain reachable.

<Example name="Truncated" component="Breadcrumb"><Truncated /></Example>

### Custom separator

`BreadcrumbSeparator` defaults to a `ChevronRight` glyph. Pass any node as
children to override — `Slash` for filesystem-style trails, `ChevronRight` for
explicit forward motion. Mix and match per crumb if it helps the hierarchy
read.

## Accessibility

- The root renders a `<nav>` with `aria-label="breadcrumb"` so assistive tech
  announces the landmark distinctly from primary navigation. Do not nest a
  second breadcrumb inside the same page.
- Use `BreadcrumbPage` for the current page — it renders a `<span>` with
  `aria-current="page"` and `aria-disabled="true"`, signalling "you are here"
  without offering a non-functional link.
- `BreadcrumbSeparator` is `aria-hidden` and `role="presentation"`; the trail
  reads as a clean list of links to screen readers, with no extra noise
  between crumbs.
- `BreadcrumbEllipsis` carries an `sr-only` "More" label and is otherwise
  hidden from AT. If the hidden crumbs must stay reachable, wrap the ellipsis
  in a `DropdownMenu` trigger so keyboard users can expand them.
- Tab order flows naturally through each `BreadcrumbLink`; the current page is
  intentionally not focusable. Keep crumb labels short so they fit on one line
  and do not wrap mid-link.
