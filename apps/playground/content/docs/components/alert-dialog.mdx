## Examples

### Destructive confirmation

The canonical pattern: a destructive trigger button opens a modal whose
`AlertDialogAction` carries the same destructive styling. The action label
restates the verb ("Delete project") so the button is unambiguous in
isolation — never label it just "Yes" or "Confirm".

<Example name="Destructive" component="AlertDialog"><Destructive /></Example>

### Controlled

Pass `open` and `onOpenChange` to drive the dialog from your component.
Useful when the confirmation is triggered programmatically — for example,
after an unsaved-changes guard fires on navigation.

<Example name="Controlled" component="AlertDialog"><Controlled /></Example>

### Title and multi-paragraph body

`AlertDialogDescription` is the accessible body and should stay short.
For additional context — caveats, side effects — render extra paragraphs as
plain `<p>` elements between the description and the footer. Only the
description is wired to `aria-describedby`.

<Example name="WithDescription" component="AlertDialog"><WithDescription /></Example>

### Long content with scrolling

When the body cannot be condensed (terms, exports, license confirmations),
constrain `AlertDialogContent` height with `max-h-[80vh]` and let it scroll.
Keep the footer outside the scroll region — `flex` layout already pins it
visually, but verify the action buttons remain reachable on small viewports.

## Accessibility

- Built on Base UI's `AlertDialog` primitive. Renders with
  `role="alertdialog"` so assistive tech announces the modal as an alert
  rather than a generic dialog.
- Focus is trapped inside `AlertDialogContent` while open. By default, focus
  lands on `AlertDialogCancel` — the safer choice for destructive flows so
  an accidental Enter does not commit the action.
- `Esc` closes the dialog and returns focus to the element that opened it
  (`AlertDialogTrigger` by default, or the controlled trigger element).
- `AlertDialogTitle` is the accessible name (wired to `aria-labelledby`)
  and `AlertDialogDescription` is the accessible body (wired to
  `aria-describedby`). Always include both — Base UI warns at runtime if
  either is missing.
- Action buttons must be self-describing. Label them with the verb
  ("Delete project", "Revoke certificate", "Sign out everywhere") — never
  "Yes" / "No" / "OK" / "Confirm" alone, which lose meaning when read out
  of context by a screen reader.
- Unlike `Dialog`, AlertDialog is not dismissible by backdrop click — the
  user must explicitly choose Cancel or Action. This is intentional: it
  prevents misclicks on irreversible operations.
