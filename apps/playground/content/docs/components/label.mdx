## Examples

### With input

The canonical pairing: a `Label` above an `Input`, joined by `htmlFor` and
`id`. Clicking the label text focuses the field, and assistive technology
announces "Username, edit text" instead of just "edit text".

<Example name="WithInput" component="Label"><WithInput /></Example>

### Required marker

There is no `required` prop on Label — render the marker as content. Pair a
visual asterisk (`aria-hidden`) with a screen-reader-only "(required)" string
so sighted users see the cue and assistive tech announces the obligation.
Mirror the state on the control with the native `required` attribute.

<Example name="Required" component="Label"><Required /></Example>

### Disabled control

Label exposes a `peer-disabled:opacity-70` style that fades the caption when
a sibling control marked `peer` is disabled. Add `className="peer"` to the
input and the label dims automatically — no extra state plumbing.

## Accessibility

- `htmlFor` and the control's `id` are required and must match. Without the
  pair, clicking the label does not focus the control and screen readers do
  not announce the caption when the user tabs into the field.
- The label's click target extends to the control: tapping the text is the
  same as tapping the input. Keep label text concise so the hit area stays
  predictable on touch devices.
- Required state must be announced, not just shown. Combine an `aria-hidden`
  asterisk with `sr-only` "(required)" text, or set `aria-required="true"`
  on the control itself.
- Do not nest interactive elements (links, buttons) inside a Label. The
  whole label is already a click target for the associated control, and
  nested interactives create ambiguous focus and click behaviour.
- For groups of controls (radio buttons, checkbox sets) that share one
  caption, wrap the group in a `<fieldset>` with a `<legend>` instead of a
  single Label — Label captions exactly one control.
